# Installable app (PWA) & phone alerts (Web Push)

Two related features, both progressive — nothing in the app depends on them:

1. **Install app** — an icon on the phone's home screen, a full-screen window
   without browser chrome. Chrome/Edge/Android offer it through the browser; iOS
   uses *Share → Add to Home Screen*.
2. **Phone alerts** — a real system notification from Web Push, delivered by a
   service worker **even when the app is closed**. No vendor account, no app
   store, no per-message cost: the site signs its own messages with a VAPID key
   pair it generates (`php artisan push:keys`).

The in-app bell still updates live while a page is open; Web Push is the half
that works with the app closed.

## Turning phone alerts on (once per server)

1. **Tables**

   ```bash
   php artisan migrate --force
   ```

2. **Key pair**

   ```bash
   php artisan push:keys
   ```

   Paste the two printed lines into the server's `.env` (never commit them) and
   keep the private key as safe as `APP_KEY`:

   ```
   WEBPUSH_ENABLED=true
   WEBPUSH_PUBLIC_KEY=BF...
   WEBPUSH_PRIVATE_KEY=...
   WEBPUSH_SUBJECT=mailto:noreply@your-school-domain
   ```

   Then `php artisan config:clear` (or `config:cache` on deploy).

3. **The per-minute cron** (the outbox is drained by the scheduler):

   ```
   * * * * * cd /path/to/app && php artisan schedule:run >> /dev/null 2>&1
   ```

   No queue worker is involved: `push:send` delivers what `Notification` queued.

Replacing the pair (`push:keys --force`) invalidates every existing
subscription — each user must press **Enable phone alerts** again.

## How a user turns it on

1. Install the app (top bar **Install app**, or the browser menu / iOS *Add to
   Home Screen*).
2. Open **Notifications** → **Enable phone alerts** → *Allow*.
3. The phone now buzzes for every in-app notification — broadcasts, messages and
   library additions follow automatically because each one writes a notification
   row — even when the app is closed.

**iPhone:** Web Push only works in an **installed** PWA (iOS 16.4+). The card
says so until the app is opened from the home screen; then the same button works.

## Requirements

* **HTTPS** (or `localhost`). Service workers and the install prompt do not exist
  on plain HTTP; a LAN IP such as `http://192.168.x.x:8000` is not enough.
* The manifest, the worker and the icons live in `public/`, i.e. the document
  root — nothing extra to configure on cPanel.

## Verifying

1. Chrome DevTools → **Application → Manifest**: no errors, icons listed,
   installability green; **Service Workers**: `service-worker.js` activated.
2. Press **Enable phone alerts** on `/notifications` → `push_subscriptions` gets
   a row (`user_id`, `endpoint_hash`, `last_seen_at`).
3. Send something that creates a notification (a broadcast, a message, a
   library link…) or run:

   ```bash
   php artisan push:test <user-id>
   ```

   The in-app bell is instant; the phone follows within about a minute (or at
   once with `php artisan push:send`).
4. **iPhone/iPad install button** — no iPhone, Mac or Xcode needed. The check
   renders the real `pwa-install-button` partial in Playwright's WebKit build
   and covers every branch: iPhone Safari, iPadOS (desktop Macintosh UA plus
   touch), installed/standalone, desktop with no prompt, and the Chrome/Android
   one-tap prompt.

   ```bash
   npm --prefix tools/pwa-install-check install
   npm --prefix tools/pwa-install-check run install-browser
   npm run test:pwa-install
   ```

   It exits non-zero on a regression, so it can gate a release. The first
   `install-browser` downloads WebKit (~100 MB) once; the script itself is
   `tools/pwa-install-check/check.mjs` and runs on Windows, macOS and Linux.

## Troubleshooting

| Symptom | Check |
|--------|-------|
| No **Install app** button | HTTPS and a hard reload. The button appears on Chrome/Edge/Android (one-click prompt) and on iPhone/iPad, where it opens the *Share → Add to Home Screen* steps. It hides itself once the app is installed. |
| Card says alerts are blocked | The user answered *Block* once — allow notifications in the browser's site settings, then reload. |
| `push:send` says "not configured" | The two `WEBPUSH_*` keys in *that* server's `.env`, then `php artisan config:clear`. |
| "no device on file" | The user must press **Enable phone alerts** on that phone (each browser is its own device). |
| Row stays `queued` | The `schedule:run` cron is missing, or `push:send` is not in the schedule (`php artisan schedule:list`). |
| `HTTP 401/403` in the log | The VAPID pair changed after the device subscribed — press Enable again. |
| Phone silent after a redeploy | A rotated key pair, or the phone's battery optimisation stopped the browser. |

```sql
-- who is reachable?
SELECT user_id, COUNT(*) AS devices, MAX(last_success_at) AS last_ok
FROM push_subscriptions WHERE disabled_at IS NULL GROUP BY user_id;

-- what is stuck?
SELECT status, COUNT(*) FROM push_messages GROUP BY status;
```

## Tests

`tests/Feature/WebPushTest.php` pins the encryptor against the **RFC 8291
Appendix A test vector**, verifies the VAPID ES256 signature the way a push
service does, and covers the dormant state (no keys → nothing queued or sent),
device rows, the outbox, `push:send` outcomes (201 sent, 410 disables the
device, 500 retries then fails), the `/push/*` endpoints, the notification →
push hook and the page wiring.

`tests/Feature/ProgressiveWebAppTest.php` asserts the manifest is valid JSON,
every icon it names exists, a maskable icon is present, the layout links the
manifest and the PWA script, the install button is rendered, and the worker
keeps its `install` / `activate` / `fetch` / `notificationclick` handlers.

```bash
vendor/bin/phpunit --filter 'WebPushTest|ProgressiveWebAppTest'
```

`tools/pwa-install-check/check.mjs` is the browser-side half: it runs the real
install-button partial in Playwright's WebKit build and asserts the iPhone,
iPadOS, installed, desktop and Chrome/Android prompt branches (see **Verifying**
step 4).

## Regenerating the icons

```powershell
powershell -ExecutionPolicy Bypass -File scripts\make-pwa-icons.ps1
```

The script draws them from `public/images/apple-touch-icon.png` (the largest
clean copy of the mark in `public/`). Replace that file with a 512×512 original
if the school supplies one, then re-run. Bump the icon filenames when the
artwork changes — installed apps cache an icon by URL.
